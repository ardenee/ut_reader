# UE1 O06 — object/property serialization acceptance

Updated 2026-10-21. **IMPLEMENTING — NOT ACCEPTED.**

This operation is concerned with bytes serialized by each source UE1 generation's object/property serializers. It is distinct from O07, which will validate/extract the pixel, audio, geometry or external/bulk contents that an O06 serializer locates, and O10, which checks actual runtime engine loading and end-to-end behaviour. Successful header parsing is NOT object/property acceptance.

## Critical source-defined differences

- 1996 v9/v10 uses FGlobalResourceManager raw UResource structures. Resource data is not a classic UE1 tagged-property stream. Registered `UTexture` derived native fields and `UDatabase` subclasses UTextBuffer/UBuffer/UArray/UEnum are decoded using 32-bit layouts; on-disk resource-pointer and FName words are NOT interpreted as actual loaded pointers/names.
- 1997 v22/v23 uses UObject::SerializeHeader: FExecStackMain (optional node/code fields) then UClass::SerializeBin(PROPBIN_PerObject). The reader now extracts UClass::SerializeHeader member schema, FProperty descriptor definitions and native instance values where the class schema is locally available. Missing external/inherited class schemas or unsupported class-specific SerializeData remain explicitly unresolved.
- Classic Unreal v1.200 UObject::Serialize serializes GObj.TempNum/TempMax when version<40, MainFrame for version<47 even when RF_HasStack is clear; later versions serialize a frame only when flagged. Pre-v57 state and pre-v58 group FName fields follow tagged properties.
- Version 35 object property data uses a compact package reference in the genuine DProj corpus even when the tag size field is 4; this is recorded as a version-scoped corpus exception, not asserted to be a native-runtime trace.
- v400 FPropertyTag type/size/array rules and UTexture/UFont/USound/UPalette/FireTexture class serializers are implemented for records represented in the pinned corpus. Unprocessed color/audio/mip bulk bytes belong to O07, not a false property decode.

**1996 native UFont update:** Epic `UnRes.h::FFontCharacter` stores four 32-bit signed glyph coordinates/dimensions. `UFont` has 88-byte header (UResource+UDatabase+one texture pointer) with `Num*16` bytes of glyph data. Reader and native staging decode glyph records but leave texture pointer fixup not-evaluated. Source-defined v9/v10 tests: 14/14. The 1996 sound/header and original resource database verifiers remain independent.

**1997 native inheritance test:** `verify-ue1-original-unrealfile-inheritance.php` verifies that `UClass::SerializeBin` processes the current class's `PROPBIN_PerObject` properties before its parent class, matching `FPropertyIterator` (v0.867 `UnClass.h`). Dedicated source-defined v22/v23 tests: **12/12**, including local inheritance, invalid ResMap, cycle rejection and unresolved/non-class parent refusal. External UClass provider loading remains an O06 gap.

**1996 geometry update:** Source-defined `UVectors` (3 float32 and fourth raw W/flags word), `UVertPool` (two signed INT32 indexes and `NumSharedSides`), `UBounds` (`FBoundingRect` min/max, two full 16-byte FVectors), and `UTerrain` (four signed INT32 grid bounds, 608-byte fixed derived header) are decoded by `CatalogUE1OriginalResourceGeometryReader`. On-disk `HeightMaps`, `TileMaps` and `TileRefs` remain raw unresolved words, not live resource pointers. Verifier `verify-ue1-original-resource-geometry.php` passes **40/40** v9/v10 positive/negative/staging cases, followed by native staging and isolated MySQL tests. These are source-defined binary fixtures, not original compiled 1996 oracle results.

**1996 UMeshMap update:** Epic v0.84a `UnRes.h::UMeshMap` native header is 108 bytes (mesh reference, `MaxTextures`, `AndFlags`, `OrFlags`, 16-byte scale FVector) and its `QueryMinSize` is `MaxTextures * 4` bytes of texture reference words (`UnMesh.cpp`). `CatalogUE1OriginalResourceMeshMapReader` decodes these typed native fields without fabricating pointer fixups. Source-defined v9/v10 acceptance: **10/10** including malformed array count, short header, and unverified staging; isolated MySQL remains green.

**1996 UScript structure:** The native v0.84a `UScript` header is 112 bytes, with class raw reference, `Length`, `NumStackTree`, `CodeOffset` and 5 padding words. A `FStackNode` is decoded using the source's three 8-byte links, five INT offsets/counts, 32-bit nesting enum, 16-bit FName and 4 flag bytes (56-byte naturally aligned record). `QueryMinSize=Length` and stack/code offset bounds are checked, but VM opcodes and runtime fixups remain explicitly not decoded. The source-defined v9/v10 script verifier passes **12/12**. The earlier failed run caused by a mistaken *valid* 57-byte code offset is preserved in the append-only journal alongside the corrected PASS.

**1996 UMesh update:** Source v0.84a `UnMesh.cpp::GetMeshResInfo` computes six contiguous arrays from maximum capacities: FMeshTriangle (16), packed FMeshVertex (4), FMeshVertLinkIndex (8), WORD vertex links (2), FBoundingRect (32), and FMeshAnimSeq (16). New `CatalogUE1OriginalResourceMeshReader` validates the 176-byte derived mesh header and `TotalMax`, and decodes active array records while retaining raw FName references. Native v9/v10 test evidence **14/14** plus source staging/MySQL. This is binary layout verification, NOT engine animation, linked names or full object execution.

**1997 native FProperty correction:** Epic v0.867's `FRotation` stores signed `ANGLE_TYPE` (INT32), not unsigned DWORD. `CatalogUE1OriginalUnrealfileBinaryPropertyReader` now sign-extends all three serialized rotation fields; the source-defined class schema acceptance covers **nine** instance types (Int, Bool, Object, String, Rotation, Float, Vector, Name, Byte) across v22/v23, including negative and INT32-min angles, after correcting the native fixture count. Inheritance, unverified staging and isolated MySQL regression checks remain passing. This does not certify dynamically linked external class schemas or all class-specific SerializeData implementations.

### Critical 1996 vs 1997 FVector serialization ABI correction

Epic **v0.84a** `Src/Inc/UnMath.h::FVector` has `X,Y,Z` floating-point components **and a fourth 32-bit `W`/flags union word**, so native size is **16 bytes**, not 12. `FBoundingRect` contains two such vectors and is **32 bytes**, not 24. This invalidated earlier **synthetic fixture** passes for the 1996 UVectors/UBounds record sizes, native MeshMap Scale/header, and UMesh origin/bounds/header and frame data. The corrected source layout is UVectors=16 bytes, UBounds=32 bytes, UMeshMap header=108 bytes, UMesh header=176 bytes, UMesh FBoundingRect frame=32 bytes. The corrected verifiers are `verify-ue1-original-resource-geometry.php` **40/40**, `verify-ue1-original-resource-meshmap.php` **10/10**, and `verify-ue1-original-resource-mesh.php` **14/14**; their source fields retain the fourth word verbatim instead of interpreting engine flags as a normal coordinate. Epic **v0.867** `Src/Inc/UnMath.h::operator<<(FArchive&,FVector&)` serializes **only X,Y,Z**, making the 1997 archive FVector exactly 12 bytes. Do not apply 1996 native struct sizes to 1997 per-field archive encoding. Earlier incorrectly sized verifiers remain in the append-only test evidence; corrected passes supersede their source-parity claims.

**1996 BSP native member decoding and compiled ABI verification (2026-10-21):** The `CatalogUE1OriginalResourceBspReader` implements source-defined `UBspNodes` (record 64 bytes, header 1,636 bytes including 64 FZoneProperties records) and `UBspSurfs` (record 48 bytes, header 84 bytes), using `Src/Inc/UnRes.h` and `Src/Engine/UnModel.cpp`. It decodes active node planes, zone masks, index links, flags and native surface member fields; pointers remain serialized raw words, and zone visibility algorithms are not claimed executed. `verify-ue1-original-resource-bsp.php` passed **24/24** v9/v10 synthetic source-defined cases, including bounds failures and unverified staging, with MySQL acceptance separately passing. `catalog/compliance/evidence/o06/ue1-1996-msvc-abi.cpp` is an isolated **source-transcribed** Epic v0.84a layout probe, compiled by actual x86 MSVC via `verify-ue1-original-1996-msvc-abi.php` (**4/4 checks**). It demonstrates 32-bit ABI struct sizes and compiler layout, **not** runtime engine equivalence or compilation of untouched Epic code.

**1996 UPolys source-native FPoly (2026-10-21):** Epic v0.84a defines 20 full 16-byte FVector members in each FPoly, plus flags, two raw resource pointers, two FName WORDs, three signed indexes and four bytes. The compiled x86 MSVC ABI proof confirms **352 bytes** per FPoly. New `CatalogUE1OriginalResourcePolysReader` decodes these values without runtime pointer fixups; `verify-ue1-original-resource-polys.php` passed **14/14** v9/v10 source-defined fixtures and corruption/staging cases; isolated MySQL also passed. This does not execute UnrealEd polygon operations.

**1996 ULightMesh:** `ULightMesh` is an 84-byte source-native resource header followed by `NumIndices` native `FLightMeshIndex` entries (**100 bytes each** under x86 MSVC /Zp4), with total `NumDataBytes` bytes. `CatalogUE1OriginalResourceLightMeshReader` decodes light index dimensions, spacing, raw actor references, shift fields and bounded sample-data spans without interpreting O07 lighting samples. Source-defined v9/v10 tests pass **14/14**, x86 ABI static assertions **4/4**, and staging plus isolated MySQL pass. `NumIndices`/`NumDataBytes` and `MAX_POLY_LIGHTS=16` bounds are enforced.

**Source-defined not-saveable exclusions (2026-10-21):** Original Epic v0.84a `UCamera::Flip` (`Src/Engine/UnCamera.cpp`), `UPlayer::Flip` (`Src/Engine/UnServer.cpp`), and editor-only `UTransBuffer::Flip` (`Src/Editor/UnEdTran.cpp`) explicitly throw `resource type not saveable`; those are NOT on-disk O06 serializers to invent. `RES_Ambient=30` exists in `UnRes.h` but a scan of all **214** `.cpp`/`.h` files in the pinned v0.84a source found no `AUTOREGISTER_RESOURCE(RES_Ambient,...)`. The executable source-backed verifier `verify-ue1-o06-original-saveability.php` passes **8/8**, recording SHA-256 source identifiers. This exclusion applies to original v0.84a only, and does not imply other UE1 versions cannot implement a corresponding class.

**Test fingerprint dependency hardening:** O06 test journal now fingerprints the pinned original **1996 v0.84a and 1997 v0.867 source files** along with PHP readers, CLI/staging code, test script and the x86 ABI probe, to prevent stale passes being incorrectly reused after a source change. This global fingerprint update invalidates historical fast-skip fingerprints; it does NOT erase old PASS/FAIL evidence. New named tests and code-affected acceptance checks are executed and logged individually; do not rerun unrelated prior suites just for bookkeeping.

**1996 model and level native headers (2026-10-21):** Compiler-transcribed 32-bit Epic ABI proves `FScale=24`, `FBoundingVolume=48`, `PBeginPlay=8`, `UModel=392`, `ULevel=172` bytes. Epic v0.84a `UModel::QuerySize` returns zero; `ULevel` inherits the zero-data `UResource` format. `CatalogUE1OriginalResourceModelLevelReader` decodes source native model reference words, full 16-byte FVector values including W/flags, signed rotation, FScale, two bounds, editor properties, and ULevel state/begin-play flags and all references. Missing link fixup/runtime state is explicitly not verified. Verifier `verify-ue1-original-resource-model-level.php` passed **20/20** v9/v10 synthetic fixture/negative/staging tests, isolated MySQL and x86 MSVC ABI proof passing separately. Original 1996 UClass and UActorList class-member data remain open.

**1996 UClass FClassProperty table (2026-10-21):** Native `FClassProperty` records are **32 bytes** (`UnClsPrp.h` and x86 MSVC ABI static assertion), distinct from v0.867 FProperty. `UClass::QueryMinSize` uses Num*32 and QuerySize Max*32; `CatalogUE1OriginalResourceClassPropertyReader` decodes names (native FName WORD indexes), category, 11 enum types (0..10), flags, offsets, dimensions, bin and conditional 32-bit enum/class/bitmask union, keeping referenced names/pointers unresolved. Source-defined v9/v10 fixture and mutation tests **12/12**, x86 ABI proof **4/4**, staging/MySQL PASS. **Incomplete:** the full 1996 `UClass` header includes a default `AActor`; native class header/default-actor members and referenced actor data are not decoded. Do not mark original UClass O06 accepted merely for its property descriptor table.

**Original 1996 AActor/UActorList/UClass embedded default actor (2026-10-21):** Source-extracted `Root.h` fields, `UnRoot.h::FActorPrivate`, `UnClass.h` and `UnActLst.h` were compiled with modern x86 MSVC under 4-byte packing. `AActorBase=304` bytes, `AActor=1148`, `UActorList` native header=116, `UClass` header=1272, embedded default actor begins at offset 124. The native actor name field is at offset 144, iMe at 152, PropertyPad at 304, private segment at 948. `CatalogUE1OriginalResourceActorReader` decodes class reference, Location/Velocity with 16-byte original FVector, signed rotations, native name indices, signed actor index and relevant UClass/UActorList header metadata while preserving SHA-256 raw actor identity. `verify-ue1-original-resource-actors.php` passes **24/24** v9/v10 fixtures/mutations/staging, `verify-ue1-original-1996-actor-abi.php` passes **4/4** compiled x86 source-derived assertions, MySQL acceptance PASS. **Open:** this is core actor metadata, not the entire 304-byte AActorBase member list, 643-byte property pad, 200-byte private segment, 1996 inherited property interpretation, or runtime references. It does NOT close O06 by itself.

## Durable test journal and timeout recovery

Every O06 test is invoked through `catalog/bin/run-ue1-o06-tests.ps1 -Tests <named verifier>` rather than from an unrecorded terminal loop. `UE1-O06-TEST-EVENTS.jsonl` is append-only: it writes `STARTED` before invoking PHP, then `PASS`/`FAIL`, exit code, elapsed time, Git commit, source/test SHA-256 fingerprint and the persisted full stdout/stderr file under `evidence/o06/`. `UE1-O06-TEST-STATUS.json` is refreshed before and after **each** test, and identifies the latest state. A STARTED row with no later terminal event is **interrupted**, not passed. Previous failures remain in the event history; fixed tests get a separate new run entry. Tests can be skipped only when the *latest* run for the same target and exact source/test hashes passed; `-Force` re-executes. Use `-TargetRoot 'Z:\Apache24\htdocs\unrealdb'` to journal PRD acceptance separately. Do not assume historical pre-journal passes were logged by this runner; those remain in prior acceptance documentation.
