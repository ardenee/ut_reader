- `catalog/src/Infrastructure/Metadata/Uedb5Ue5ScriptRuntimeEnumerationAudit.php` offers **`inspect($packages, $registeredScriptIndices, $withEditor, $doCheck)`**, returning expected source-defined eligibility and branch decisions from explicitly supplied inputs. The audit is never itself a source of such observations; it labels its result `runtime_registry_authoritative=false`. ## B015-1 non-editor DO_CHECK runtime observation (18 October 2026)

The existing real UE5.8.3 **UnrealPak.exe** trace is a genuine non-editor `WITH_EDITOR=0`, `DO_CHECK=1`, `ALT2_ENABLE_SCRIPT_IMPORTS_DEBUGGING=0` engine runtime. At `FGlobalImportStore::RegistrationComplete`, the original source's `#elif DO_CHECK` branch runs `FindAllScriptObjects(/*bVerifyOnly*/true)`. Its actual trace reports **six** eligible `/Script/` packages, **583 initial** script objects, **268 nested-public** script objects, and a final `registration_complete|editor=0|check=1|debug=0|count=851`. The original raw log remains `D:\Temp\uedb5-ue583-runtime\probe-unrealpak-typed-direct.log`, SHA-256 `94E8C271FC147B9ACFF29183A0F95F41382C0EA7BB1624EEFD33B9F2DAC0C560`. Existing strict inspector reports **858/858** accepted typed events, zero rejections. This proves the *configuration executes and completes registration*, **not** that a deliberately missing live index triggers its check-only diagnostics; the trace contains no deliberately injected missing-key case.

A separate genuine cooked `UnrealGame.exe` with `WITH_EDITOR=0` completed startup and PreCDO 23,672-element cooked ScriptObjects diagnostic map load; SCRIPT-005's real compiled fallback test is separately verified at commit `73f5c1d7`. The cooked game is a different configuration from the UnrealPak DO_CHECK trace. Neither run establishes the no-check build branch on a controlled eligible object set nor Verse VNI UHT-positive/UHT-negative runtime object selection or VM ScriptCells registration. The original **B015-1 remains partial**; do not promote it by conflating these separate runtimes.
