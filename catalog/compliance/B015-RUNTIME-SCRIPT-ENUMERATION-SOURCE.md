**Existing original operation:** `UE5-583-B015-1`, the first of two operations in `B015-ue5-script-registration-recursion.json`. **Disposition: partial.** Its sibling **B015-2** remains verified for *offline recursive imported-package requirements*, not for async runtime execution. No new B operation or difference number was created by this audit, because UnrealDB currently has no live `FGlobalImportStore::ScriptObjects` registry and no demonstrated incorrect *offline* behavior in this source branch.

## Executable evidence and guarded consumer reconciliation

- `catalog/src/Infrastructure/Metadata/Uedb5Ue5ScriptRuntimeEnumerationAudit.php` offers **`inspect($packages, $registeredScriptIndices, $withEditor, $doCheck)`**, returning expected source-defined eligibility and branch decisions from explicitly supplied inputs. It accepts only observed package paths, compiled-in flags, lists of nested objects, `RF_Public` flags, and explicit UHT provenance for public Verse VNI objects. It never reads Epic runtime memory or touches persistent SQL.
- The caller must separately capture *actual* `UPackage` and `UObject` runtime fields, plus actual keys in `FGlobalImportStore::ScriptObjects`. The audit is never itself a source of such observations; it labels its result `runtime_registry_authoritative=false`. It rejects malformed typed indices, duplicate observations, unrelated object outer paths and missing VNI UHT flags; case-insensitive path-hash collisions are recorded as ambiguous without selecting a winner.
- `catalog/bin/verify-uedb5-b015-runtime-script-enumeration-source.php` pins the Epic C++ file and independently tests **23** source and fixture assertions: case-sensitive package categories, compiled-in eligibility, editor package identities, nested `RF_Public` paths, UHT-only Verse VNI exclusion, non-editor check-only and no-check branches, collision/invalid observation fail-closed behavior, actual typed GetRecipes hash, and UnrealDB resolver's conservative `unresolved/script_object_runtime_context_unavailable` result.
- `catalog/bin/verify-uedb5-b015-runtime-script-enumeration-acceptance.php` runs **six drivers and 18 acceptance assertions**, including source-identical apart from normalized line endings Epic native source execution under four build configurations, including B003 registration/diagnostics, B013 independent native hashing, B002 ScriptImport runtime boundary, and this new source oracle. It must not flip B015-1 to verified without an actual Epic runtime evidence session.

## Outstanding runtime acceptance — exact data to capture

No built `UnrealEditor.exe` or `UnrealEditor-Cmd.exe` was present in the inspected UE5.8.3 source checkout. Source and cooked data alone cannot establish a live global registry. To close the original **B015-1**, an instrumented Epic run in a supported editor and non-editor configuration must capture (a) compiled-in package names/flags; (b) `GetObjectsWithOuter` results with nested visibility and `RF_Public`; (c) `IsUHTGeneratedVerseVNIObject` outcomes; (d) registered keys before and after `RegistrationComplete`, including a missing-key check-only branch; (e) at least one excluded compiler-generated Verse object; (f) VM ScriptCells separately; (g) any hash duplicates and their live ownership, and (h) runtime build macros/cooked-debug state. A source-integrated runtime harness or independently captured authoritative event trace must then be compared against these source-mapped assertions.

UnrealDB cannot manufacture registration outcomes from the 54,968-entry Satisfactory *diagnostic* ScriptObjects chunk, and no uploaded/imported package was modified. **B015-1, SCRIPT-003, SCRIPT-004 and SCRIPT-005 remain partial** pending runtime proof, and overall global source compliance remains unverified.

This is **not a UE5 live-runtime session** and does not close any partial original operation.
