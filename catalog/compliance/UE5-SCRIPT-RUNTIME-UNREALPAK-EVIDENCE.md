## Discovered instrumentation mismatch

Pinned Epic `AsyncLoading2.h::FPackageObjectIndex` specifies `IndexBits=62`, `ScriptImport=1`, and `Value()` returns `TypeAndId & IndexMask` (the **untyped payload**). The original probe logged `%016llX` of `.Value()`, but the independent inspector correctly required the complete typed ScriptImport identity (top two bits `01`, hex leading nibble `4` through `7`). All 851 `add` events were rejected with `event_semantics_rejected`; the 6 `eligible_package` and 1 `registration_complete` events passed. This was a **trace contract defect**, not proof of an UnrealDB package-index discrepancy.

Fix in `catalog/bin/prepare-ue5-script-runtime-trace.php`: all 11 logged ScriptImport index sites now OR the source-defined `(1ull << 62)` bit into the reported 62-bit payload. The preparation regression now explicitly checks all 11 full typed-index sites, without loosening the inspector's checks. The generated patch still affects only a disposable source copy, never canonical Epic source or the UnrealDB runtime parser.

For independent diagnostic confirmation, a **separate** copy of that original 858-event real log was reconstructed by restoring only the omitted type bit on 851 index fields. The unchanged trace inspector accepted 858/858 events with zero malformed or semantic rejections: 583 `add:initial_object`, 268 `add:nested_public`, 6 `eligible_package:script`, and 1 `registration_complete`. No raw log was changed; the reconstructed local copy is `probe-unrealpak-typed-reconstructed.log`, report `probe-unrealpak-typed-reconstructed-inspection.json`. Its passing inspection is a **derived diagnostic** and must not be misrepresented as an unmodified probe capture.
