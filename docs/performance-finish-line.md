# Performance finish-line phase

This document records the production-scale protections currently expected from the catalog runtime. It is not a historical statement that every older implementation remains authoritative.

## Background Jobs

### Search projection

`ue_background_job_search` is the compact FULLTEXT projection used for broad Background Jobs search. `PdoBackgroundJobBrowserQuery` owns projection/search SQL; the HTTP endpoint no longer constructs it.

Short terms may fall back to bounded `LIKE` against the compact projection. Compatibility `job-status.php` deliberately preserves its historical wildcard search contract for secondary callers.

### Indexed display status

Migration `202608080001_background_job_display_status.php` adds a stored generated `ue_background_jobs.display_status` column derived from queue `status` and `result_json`.

Live Failed/Completed filtering and counters use this column instead of grouping by `JSON_EXTRACT(result_json, '$.status')` on every poll. Because it is generated by MySQL, it is not a second mutable source of truth.

### Parallel claiming

`PdoJobClaimer` uses `FOR UPDATE SKIP LOCKED` rather than a queue-wide claim mutex. Resource-class and concurrency-key admission remain enforced with short scoped coordinator locks and indexed checks.

This allows unrelated resource classes to claim concurrently while preserving the configured class limits and per-key exclusion semantics.

### Single lifecycle implementation

All workers now use `PdoJobQueue`. Enqueue, claim, leased lifecycle and recovery are delegated to focused collaborators; the former `WorkerJobQueue` duplicate implementation has been deleted.

## Exact-count cache

`catalog_count()` may use a short-lived cache for eligible large-table aggregates. Counts remain authoritative on cache miss, inside transactions, and when `UNREALDB_COUNT_CACHE_DISABLED=1` is set.

The count cache is a bounded-staleness performance layer, not catalog state.

## Upload/import hot path

Upload Bucket package processing no longer uses Reflection to invoke private methods on a monolithic processor.

The explicit production path is:

```text
CatalogBucketIdentityProcessor
  → CatalogBucketPackageOperationsService
      → CatalogPackageIdentityHasher
      → CatalogUploadBucketStorage
      → CatalogUnverifiedPackageIndexer
```

Ordinary browser uploads reuse MD5/SHA-1 calculated while bytes were produced and verify those hashes while creating the isolated working copy. Redirect wrappers are decompressed before authoritative package identity is checked.

## Verified metadata

Verified package metadata is represented by the compact per-file metadata/lookup architecture. Retained raw Names/Imports/Exports compatibility access is transitional and audited; it is not the preferred authoritative runtime read path.

`php catalog/bin/audit-legacy-runtime-references.php` detects unapproved direct runtime references and any return of the removed `ue_search_documents` projection.

## Page-time diagnostics

Shared database helpers record aggregate application time, SQL time and query count per route. Responses can expose `Server-Timing`, `X-UnrealDB-Query-Count` and count-cache diagnostics. Slow requests are written to the normal PHP/Apache error log.

`UNREALDB_SLOW_REQUEST_MS` controls the slow-request threshold.

## Deployment / validation

Before representative load testing:

```text
php catalog/bin/migrate.php status
php catalog/bin/migrate.php migrate --dry-run
php catalog/bin/migrate.php migrate --lock-timeout=60
php catalog/bin/migrate.php verify
php catalog/bin/audit-legacy-runtime-references.php
php catalog/bin/verify-architecture-refactor.php --database
```

Then validate with real Upload Bucket/import/dependency jobs and review page-time diagnostics while the configured worker pool is active.

## Completion criteria

The current performance/refactor phase is ready for production-style testing when:

- all pending migrations apply cleanly;
- `display_status` and its indexes exist;
- architecture verification passes;
- the legacy metadata audit reports no unapproved runtime references;
- Background Jobs remains responsive while workers are active;
- worker active count reaches the configured resource-policy limits when independent work exists;
- queue depth/running counts decrease consistently with completed jobs;
- Upload Bucket ordinary and redirect files preserve their previous identity/deduplication/import results;
- no regression appears in unverified promotion or post-import dependency jobs.
