## Package tag and modern version preamble

The package starts with `PACKAGE_FILE_TAG` or the swapped tag. A swapped tag enables byte swapping before later fields are interpreted.

UE5 5.8.3 uses `CurrentLegacyFileVersion = -9`. A value newer than the reader understands must cause an early stop rather than guessed parsing.

For modern packages the summary serializes:

1. `LegacyFileVersion`
2. legacy UE3 version except for the special `-4` layout
3. `FileVersionUE4`
4. `FileVersionUE5` when `LegacyFileVersion <= -8`
5. `FileVersionLicenseeUE`

UnrealDB therefore records UE4 and UE5 version components separately. It must not collapse them into one generic package version.

If UE4, UE5 and licensee versions are all zero, the package is unversioned. UnrealDB records that fact and uses an explicit parser profile for interpretation; the assumed version is not treated as serialized evidence.

At `PACKAGE_SAVED_HASH`, `SavedHash` is serialized before `TotalHeaderSize`. Older layouts place `TotalHeaderSize` directly after the version/custom-version preamble.
## Summary fields implemented by the classic reader

The current reader consumes the UE5 5.8.3 summary gates needed to keep later table offsets aligned, including:

- package name / deprecated folder-name slot;
- package flags;
- name, import and export counts/offsets;
- soft-object-path count/offset;
- gatherable-text count/offset;
- Verse cell import/export count/offset;
- metadata offset;
- dependency offset;
- soft-package-reference count/offset;
- searchable-name and thumbnail offsets;
- import-type-hierarchy count/offset;
- generations and engine-version records;
- compression/chunk fields;
- asset-registry and bulk-data offsets;
- preload-dependency count/offset;
- `NamesReferencedFromExportDataCount`;
- `PayloadTocOffset`;
- `DataResourceOffset`.

Offsets are parsed for layout correctness even when the pointed-to structure is not yet projected into UEDB5.
## Name table and FName identity

Classic UE5 package tables continue to reference names through serialized `FName` index/number pairs.

UnrealDB retains both the raw index/number and the rendered text form. The rendered value is an aid for catalog/search use; the raw serialized identity remains authoritative.

## FObjectImport

UE5 5.8.3 serializes imports in this order:

1. `ClassPackage`
2. `ClassName`
3. `OuterIndex`
4. `ObjectName`
5. `PackageName` at `VER_UE4_NON_OUTER_PACKAGE_IMPORT`
6. `bImportOptional` at `EUnrealEngineObjectUE5Version::OPTIONAL_RESOURCES`

`PackageName` must always be consumed when its version gate is active, including `PKG_FilterEditorOnly` packages.

When saving filtered editor-only data, Epic may serialize `ObjectName` as a placeholder for a None `PackageName`. On load, if serialized PackageName equals ObjectName, the loader resets effective PackageName to None.

UnrealDB therefore retains both `serializedPackageName` and the post-load effective `PackageName`.
## FObjectExport

The classic UE5 export reader preserves the source-gated record rather than borrowing UE4's fixed assumptions.

Relevant fields include:

- `ClassIndex`, `SuperIndex`, `TemplateIndex`, `OuterIndex`;
- `ObjectName`;
- serialized object flags;
- serial size and offset;
- forced/client/server filtering flags;
- per-export package flags;
- editor/game and asset flags where versioned;
- `bIsInheritedInstance` from `TRACK_OBJECT_EXPORT_IS_INHERITED`;
- `bGeneratePublicHash` from `OPTIONAL_RESOURCES`;
- preload/dependency ranges;
- script serialization start/end offsets from `SCRIPT_SERIALIZATION_OFFSET` when versioned property serialization is active.

At `REMOVE_OBJECT_EXPORT_PACKAGE_GUID`, the old per-export package GUID is no longer serialized. A reader that continues consuming 16 bytes there will shift every following export field and invalidate the table.

UE5 classic export object flags are serialized through the source's 32-bit save mask. This is distinct from UE3's QWORD ObjectFlags requirement.
## Soft package references

`FLinkerTables::SoftPackageReferenceList` is `TArray<FName>` in UE5 5.8.3. The reader therefore consumes each entry as an FName rather than a legacy FString path.

These soft references remain a separate dependency class and must not be promoted to hard imports.

## Current UnrealDB implementation boundary

Implemented in `b95dfe2c`:

- dedicated `UnrealPackageReader5`;
- UE5 header routing using separate legacy/UE4/UE5 version fields;
- source-gated classic summary parsing;
- `PackageName` placeholder/reset behavior;
- `bImportOptional`;
- UE5 export GUID removal/inherited-instance/public-hash/script-offset gates;
- UE5 soft-package FName references;
- separate UE5 parser profile and reader dispatch.

Not yet implemented: UEDB5 persistence/cutover, UE5 classic `VerifyImportInner` resolver, Zen/IoStore `.utoc/.ucas` ingestion, Zen PackageId/public-export-hash resolution, and UE5-specific dependency classification.

Verification contract: `catalog/bin/verify-ue5-583-reader-contract.php`.
