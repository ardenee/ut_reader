## Package tag and modern version preamble

The package starts with `PACKAGE_FILE_TAG` or the swapped tag. A swapped tag enables byte swapping before later fields are interpreted.

UE5 5.8.3 uses `CurrentLegacyFileVersion = -9`. A value newer than the reader understands must cause an early stop rather than guessed parsing.

For modern packages the summary serializes:

1. `LegacyFileVersion`
2. legacy UE3 version except for the special `-4` layout
3. `FileVersionUE4`
4. `FileVersionUE5` when `LegacyFileVersion <= -8`
5. `FileVersionLicenseeUE`

UnrealDB therefore records UE4 and UE5 version components separately. It must not collapse them into one generic package version.

If UE4, UE5 and licensee versions are all zero, the package is unversioned. UnrealDB records that fact and uses an explicit parser profile for interpretation; the assumed version is not treated as serialized evidence.

At `PACKAGE_SAVED_HASH`, `SavedHash` is serialized before `TotalHeaderSize`. Older layouts place `TotalHeaderSize` directly after the version/custom-version preamble.

### Exact inherited UE4 component gates

UE5 5.8.3 still carries the complete `EUnrealEngineObjectUE4Version` history. Enum values must be derived by counting every C++ enumerator, including non-`VER_UE4_*` members; prefix-only counting is invalid. The audited values used by the classic reader are: EngineVersionObject 336; StringAssetReferences 384; CompatibleEngineVersion 444; SerializeText 459; LoadForEditorGame 365; CookedAssetsInEditor 485; NameHashes 504; PreloadDependencies 507; TemplateIndex 508; SearchableNames 510; 64-bit export serials 511; SoftObjectPath 514; LocalizationId 516; PackageOwner 518; NonOuterPackageImport 520; final UE4 version 522.

`GPackageFileUEVersion` for this UE5 source revision is therefore UE4 `522` plus UE5 `1018`. Unversioned classic packages must use those values as parser assumptions while retaining serialized zeroes as source evidence.

## Name table and FName identity

Classic UE5 package tables continue to reference names through serialized `FName` index/number pairs.

UnrealDB retains both the raw index/number and the rendered text form. The rendered value is an aid for catalog/search use; the raw serialized identity remains authoritative.

The legacy name-table hash words are gated by the UE4 component (Ar.UEVer() >= VER_UE4_NAME_HASHES_SERIALIZED), even inside a UE5 package. The reader must not compare the UE5 version component to this inherited UE4 gate.

## FObjectImport

UE5 5.8.3 serializes imports in this order:

1. `ClassPackage`
2. `ClassName`
3. `OuterIndex`
4. `ObjectName`
5. `PackageName` at `VER_UE4_NON_OUTER_PACKAGE_IMPORT`
6. `bImportOptional` at `EUnrealEngineObjectUE5Version::OPTIONAL_RESOURCES`

`PackageName` must always be consumed when its version gate is active, including `PKG_FilterEditorOnly` packages.

When saving filtered editor-only data, Epic may serialize `ObjectName` as a placeholder for a None `PackageName`. On load, if serialized PackageName equals ObjectName, the loader resets effective PackageName to None.

UnrealDB therefore retains both `serializedPackageName` and the post-load effective `PackageName`.

A serialized NAME_None can render as the name-map text None; the reader retains that raw FName as serialized evidence but normalizes the effective PackageName to semantic None, matching FObjectImport::HasPackageName() rather than treating None as a provider package.

`FName::IsNone()` is an identity check, not trimmed-string normalization. Exact `None` with Number zero is semantic None; whitespace-bearing names such as `" None "` are distinct serialized FNames and must remain distinct.
## FObjectExport

The classic UE5 export reader preserves the source-gated record rather than borrowing UE4's fixed assumptions.

Relevant fields include:

- `ClassIndex`, `SuperIndex`, `TemplateIndex`, `OuterIndex`;
- `ObjectName`;
- serialized object flags;
- serial size and offset;
- forced/client/server filtering flags;
- per-export package flags;
- editor/game and asset flags where versioned;
- `bIsInheritedInstance` from `TRACK_OBJECT_EXPORT_IS_INHERITED`;
- `bGeneratePublicHash` from `OPTIONAL_RESOURCES`;
- preload/dependency ranges;
- script serialization start/end offsets from `SCRIPT_SERIALIZATION_OFFSET` when versioned property serialization is active.

At `REMOVE_OBJECT_EXPORT_PACKAGE_GUID`, the old per-export package GUID is no longer serialized. A reader that continues consuming 16 bytes there will shift every following export field and invalidate the table.

UE5 classic export object flags are serialized through the source's 32-bit save mask. This is distinct from UE3's QWORD ObjectFlags requirement.
## Soft package references

`FLinkerTables::SoftPackageReferenceList` is `TArray<FName>` in UE5 5.8.3. The reader therefore consumes each entry as an FName rather than a legacy FString path. Its rendered `path` projection preserves the exact serialized FName text; it is not trimmed or path-normalized at the reader boundary.

These soft references remain a separate dependency class and must not be promoted to hard imports.

## UEDB5 classic persistence

`Uedb5Ue5ClassicSnapshotBuilder` now maps this reader into source-shaped UEDB5 staging sections without publishing SQL metadata or changing the production UEDB4 runtime.

The reader/persistence boundary preserves:

- the serialized package tag and whether byte swapping was active;
- serialized UE4, UE5 and licensee version components separately from effective assumed versions used for an unversioned package;
- parser-profile identity for those unversioned assumptions;
- raw FName index/number/text identity for classic imports/exports and soft package references;
- serialized and post-load effective `PackageName` separately;
- `bImportOptional` and the raw signed import/export package-index graph;
- export flags, filter bits, preload ranges, serial offsets and script offsets;
- explicit presence state for version-gated import/export members, so an absent source field is not confused with a serialized zero/false value;
- UE5 classic `ObjectFlags` as a canonical 16-hex-digit value while explicitly recording that the source serialized width is 32 bits with RF_Load-mask semantics.

Soft-package-reference rows are retained one-for-one with the serialized `TArray<FName>`, including a None entry if the package contains one. They remain separate from hard imports.

Verification contract: `catalog/bin/verify-uedb5-ue5-classic-persistence.php`.
