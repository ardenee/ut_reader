## UE1 v227 conditional archetype follow-up — 5 November 2026

The UE1 archive decoder and Unreal-specific source selector are **separate components**. `CatalogUE1PackageReader` reads only its explicitly selected layout: the 227k native field rule is `RF_HasArchtype && LicenseeVer>=227`, without re-parsing, searching for ambiguity, or inferring the writer from a package version. `CatalogUE1UnrealExportSourceSelector` separately compares the selected game's conditional archive layout against the alternative, rejects ambiguous or legacy-only unproven cases, and marks verified structural provenance. This selector runs on Unreal's verified intake, unverified staging, UEDB5 snapshot factory, and read-only 227k diagnostic; UT99 remains independent. The UEDB5 builder **rejects** native-raw flagged exports without source validation rather than silently losing them.

The original 227k `UnrealShare.u` provides a positive native/on-disk oracle: one `BoxRigidBody` export has signed int32 `ArchetypeIndex=13069`; omitting that field corrupts the following export table. The dedicated Unreal UEDB5 export schema `ue1.unreal.object-export.v3` retains the field only when the compiled 227k layout is structurally discriminated; original UEDB5 encode/decode, separate negative provenance fixtures and the existing genuine 4/4 UE1/UE2 reader/snapshot regression passed. The original compiled 227k loader **does not** perform ambiguity checks, and its below-227 flag clearing is an in-memory side effect; UnrealDB preserves the raw serialized flags. The 2012 227i class-runtime branch with flagged exports is **not** inferred from that evidence. See [source-selector/native-archive separation](evidence/ue1/ue1-227-native-source-selector-separation-20261105.json).
