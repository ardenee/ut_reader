# UE4.27.2 P01 — licensee version loader discrepancy corrected, 20 October 2026

**Confirmed production reader difference:** stock Epic UE4.27.2 `Engine/Source/Runtime/Core/Private/UObject/ObjectVersion.cpp` initializes `GPackageFileLicenseeUE4Version` from `VER_LATEST_ENGINE_LICENSEEUE4`; the pinned `Core/Public/UObject/ObjectVersion.h` enum contains only `VER_LIC_NONE=0`, so stock max licensee version is 0. `CoreUObject/Private/UObject/LinkerLoad.cpp` around line 1263 rejects a package with `Summary.GetFileVersionLicenseeUE4() > GPackageFileLicenseeUE4Version`. Previously `UE4/UnrealPackageReader.php` read the licensee field but did not reject >0; as a result a package with a source-defined loader-incompatible licensee version could still parse and enter UnrealDB's metadata process.

**Production correction:** dedicated UE4.27.2 reader now rejects `licensee > 0` after handling the documented unversioned marker and before reading subsequent tables. The serialized value is retained in the header for diagnostics. The check targets the pinned **stock** UE4.27.2 source; separate licensee-fork engine profiles, if ever supported, require explicit source-derived limits, not a guessed compatibility range.

**Tests:** `verify-ue427-summary-negative-branches.php` now mutates a genuine UE4.27 engine asset's licensee field to 1 and confirms rejection alongside six existing valid/corrupted/version-limit cases: **7/7** expected outcomes. `verify-ue427-real-summary-branches.php` verifies 100 authentic UE4 packages across five legacy marker layouts, 17 file versions and 51 custom entries, zero errors. `verify-ue4-427-reader-contract.php` also passed; PHP lint and git diff whitespace checks passed. No PRD SQL changes. **P01 remains open** for independent native decoded summary comparison, true swapped-endian fixture, and unversioned editor/source-config branch alignment.
