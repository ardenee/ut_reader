**Disposition: U427-P04 VERIFIED for pinned reader/source format gates** (fixed primary denominator **4/10**). P05–P10, including physical UEXP/bulk payloads, loader provider resolution and the application-wide V5 lifecycle, remain open. Do not claim full UE4.27.2 certification.

## Pinned Epic authority and actual differences

Epic engine: `L:/Source/Engine/UE4/UE 4.27.2`, revision `d94b38ae3446da52224bedd2568c078f828b4039`.
- `CoreUObject/Private/UObject/LinkerLoad.cpp::SerializeDependsMap`: in Editor/commandlet, if DependsOffset is present, one `TArray<FPackageIndex>` per `Summary.ExportCount`, with signed `FPackageIndex` elements. The real loader skips for platforms requiring cooked data, and without editor/commandlet. UnrealDB indexes the serialized table when it exists; that is a metadata-extraction decision, not a claim that the cooked loader consumed it.
- `LinkerLoad.cpp::SerializePreloadDependencies`: signed `FPackageIndex` words; scalar deserialization if byte-swapping, bulk copy if un-swapped. Event-group range metadata stays in FObjectExport (covered under P03), not collapsed into DependsMap.
- `SavePackage.cpp` / `SavePackage2.cpp`: stock UE4.27 saves `SoftPackageReferenceList` as `FName`, two signed 32-bit name-map index/instance words via `FLinkerSave::operator<<(FName&)`. Editor-only filtered packages do not save this list.
- **Historical genuine-package distinction**: the installed UE4.27 content corpus includes source-versioned UE4 packages at **513 and earlier** with a soft-reference list encoded as `FString` (signed length and ANSI bytes), whereas observed packages at **514 and later** use FName index/number pairs. The transition is established by physical asset bytes and independently executing Epic's compiled `FString` and FName primitive readers; do not misrepresent this as an explicit `if(version<514)` branch in the pinned UE4.27 `SavePackage.cpp`, which only documents its contemporary FName writer. UE4 enum `VER_UE4_ADDED_SOFT_OBJECT_PATH` = 514 is the tested corpus boundary. The separate UT4 clean-master v511 source profile already uses FName pairs and is **explicitly exempt** from the stock historical fallback.

**U427-P04-D001 (corrected)**: `UE4/UnrealPackageReader.php::readStringAssetReferences` previously always interpreted these entries as FName and skipped unresolved/invalid strings, retaining only **112/128** actual declared soft references. It now reads legacy `FString` entries for the ordinary pre-514 UE4 corpus and FName pairs for versions 514+, with an explicit UT4 v511 exception. It preserves `index`, `offset`, `path`, `source` and adds diagnostic `wireFormat` while rejecting an invalid modern NameMap index. The rebuilt full corpus retains **128/128**, matching native Epic FArchive-decoded paths and offsets. Prior secondary observation U427-S003 is resolved by this finding; do not reopen it as an additional primary operation.

**Evidence improvement**: `getDependsMap()` now includes the serialized byte offset for each DependsMap row, preserving existing reference identities and row structure. This makes native row-offset acceptance executable; it is not a separate parsing discrepancy.
