## What is NOT asserted

Epic Unreal Engine 5.8.3 does not provide UnrealDB's web/search/SQL/backup queue interfaces: those are accepted as UnrealDB production workflows exercising Epic-equivalent **file** identities and semantics, not claimed to be Epic application interfaces. Synthetic versioned and optional-segment fixtures establish decoder/source-branch behavior but are not additional commercial game cook samples. Encrypted containers require authorized keys; runtime UObject loading, shaders, animation execution, editor UI behavior, unspecified future formats and all other Unreal generations are outside this file-format audit denominator. Historical throwaway fixture tests tied to missing `.utx` files or retired IDs (e.g. 111239) were not falsely counted as passes; equivalent current isolated real-file and rollback checks support the accepted routes.

**Global compliance remains explicitly unverified:** `RECOVERY.json` is a multi-engine recovery ledger containing UE1–UE4 games with unreconciled source inventories. Its `scope_complete=false` and `compliance_claim=unverified` MUST remain unchanged until those other engines are reconciled. This global status is not a UE5-specific deficiency. The UE5.8.3 declared file-handling scope is closed; UE4.27.2 can begin as a separate engine audit, preserving these UE5 sources and acceptance records rather than rerunning them without a proven regression.

**Release checkpoint:** DEV `game-amd`, GitHub `ardenee/ut_reader/main` and PRD `Lelly-pc` synced at the final closure commit; record its hash when committed/deployed. Never mark all-engine compliance accepted from this UE5-only result.
